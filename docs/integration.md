# 宿主接入约定

本库提供计算和资源记账。NeoBot 的工具入口、授权策略和执行生命周期继续由宿主维护；当前主仓适配仍在本地整理，独立库与宿主可以分别开发、验证和发布。

## 职责划分

| 环节 | 独立库负责 | 宿主负责 |
|---|---|---|
| 读取前 | 工作集准入 | 真实身份、路径授权、链接限制、文件体积和截止时间 |
| 捕获 | UTF-8 解码、行索引、快照计算 | 文件锁、有界读取、变化检查、版本生成 |
| 分页 | 有界文本和行列游标 | 整批结果上限、owner 观察覆盖、连续翻页策略 |
| 缓存 | 额度登记、清理回调协调 | 缓存键、TTL、文件变化校验、命中及失效策略 |
| 检索 | 归一化检索字节 | 文件发现、排序、权限、ripgrep／回退进程、超时及总结果预算 |
| 写入 | 当前无直接写入 API | 批量编辑、无变化判断、完整读取要求、版本复查、原子提交 |
| PTC | 有界值校验及深复制 | AST 白名单、逐次工具授权、赋值边界、步数、工具数、取消和程序超时 |

本库不导入 NeoBot，不接收聊天 owner 或管理员凭据，不根据 `version` 参数决定文件是否可写。

## 文件工具的接入顺序

1. 根据真实调用上下文检查路径和工具权限，拒绝不允许的链接或跨域访问。
2. 依据源文件大小，使用共享 `FILE_IO_RESOURCES` 预留工作集。准入须先于文件锁，避免持锁等待全局资源。
3. 在宿主文件锁内打开文件，检查体积与身份，执行有界读取并生成版本。
4. 把已授权字节和宿主版本交给 `Snapshot.from_bytes()`。计算返回及本次处理结束前一直持有工作集预留。
5. 用 `read_page()` 构造结果，按 `start`／`end` 为当前 owner 累计自己的观察范围；共享底层内容不共享“已读完整文件”的权限。
6. 需要长期缓存时，按 `snapshot.cost` 调用 `retain()`。额度不足仍可正常返回结果，但不保留新缓存。
7. 每次命中缓存仍执行必要的权限、实际打开和文件变化检查；服务内修改、移动或删除主动使相关缓存失效。
8. 写入前仍做完整版本比较及提交前复查，随后执行原子提交。缓存命中和无变化写入都不能跳过这些步骤。

底层快照可在多个 agent 间共享。宿主应复用缓存中的快照或其 `share()`，避免各 agent 重新读取和创建相同内容。`for_search()` 返回的快照应存回宿主缓存，避免重复准备检索输入；宿主也应更新相应成本记账。

## PTC 的接入顺序

1. 每次运行持有独立环境和资源计数；不可复用上次运行的可变环境。
2. 根据程序额度构造 `PtcValueKernel`。原生能力不可用、深度超过 128 或额度无法在本机表示时，选择宿主的兼容回退。
3. 赋值、向工具传参和接收工具结果时调用 `copy()`，保持容器隔离。不能为了提速把这些边界全部改成 `validate()`。
4. 变量更新和循环变量变化后，对整个环境调用 `validate()`；结果输出时，用 `byte_limit` 再检查包含日志和结果的整体预算。
5. 原生内核不识别解释器专用异常对象。宿主应先按既有规则处理异常绑定，不能把任意宿主对象交给值内核。
6. 各次调用传入相同程序截止时间的剩余秒数；同时保留 AST 检查、工具白名单、实际调度器授权和异步让出。
7. 把 `PtcValueError.code` 转为宿主不可被模型程序捕获的解释器错误，沿原有取消和超时路径清理工具任务。

只在一次遍历内跟踪祖先来识别循环；重复别名仍逐次计算总额度。宿主不应跨调用缓存可变容器的旧统计来跳过完整复查。

## 多 agent、锁与内存

- 同一解释器复用模块级 `FILE_IO_RESOURCES`，不要按 agent 或沙箱各建一套默认池；主动创建新的 `FileIoResources` 意味着另起独立额度。
- 原生快照不可变，文件计算可以释放 GIL；PTC 数据仍是可变 Python 容器，原生遍历保持 GIL。
- 缓存应支持弱引用及 `expire()`，使用自身锁保护条目，释放或关闭时准确归还记账。
- 协调器调用 `expire()` 前已释放自身锁；宿主清理时可以拿缓存锁再归还额度，不能反过来引入持协调器锁等待缓存锁的路径。
- 缓存被淘汰时，在途请求仍可能持有快照；其工作集预留要等本次处理结束才释放。
- 多进程各自计数。工作集和缓存上限不是 RSS 硬限制，也不能替代操作系统级沙箱或文件系统事务。

## 子模块与二进制依赖

源码子模块用于固定内核源码、审查改动和联调。`git submodule update` 只更新源码，不会下载 CI artifact，也不会让已运行的 Python 自动加载新二进制。

运行时使用已安装的 wheel。正式整合后由宿主声明经过验证的包版本，uv 选择匹配平台和 Python ABI 的 wheel；不把子模块路径默认写为 `tool.uv.sources`，以免普通部署临时编译 Rust。

当前先独立整理工具库和平台产物，再统一宿主的工具入口与依赖。自动下载二进制、首次启动安装、MCP 服务以及完整文件工具 API 都需要后续明确实现，不能由现有子模块结构推断已经支持。
